# Guestbook Memory Bank

Realtime Guestbook의 현재 상황과 다음 작업을 짧은 한국어로 기록한다.
기준 문서는 링크로 연결하고, 노트는 초보자가 이해할 수 있는 한두 문장 중심으로 작성한다.
이 스킬은 기록 관리 지침이며 세션 시작 시 자동 실행되는 훅은 아니다.

## 프로젝트 확인과 읽기

이 파일의 디렉터리에서 `../../..`가 방명록 프로젝트 루트다.
현재 작업 폴더가 그 루트 또는 하위인지 확인하고, 아래 기준 문서로 프로젝트를 식별한다.
다른 프로젝트이거나 대상을 확인할 수 없다면 파일을 쓰기 전에 작업 대상을 확인한다.
상위 Git 저장소 전체나 사용자 홈을 기록 루트로 사용하지 않는다.

존재하는 파일을 다음 순서로 읽는다. 없는 문서는 없다고 알린다.

1. [AGENTS.md][agents]: 적용 지침과 작업 범위
2. `.memory-bank/`의 기본 문서 6개: `project-brief.md`, `active-context.md`,
   `progress.md`, `decision-log.md`, `next-actions.md`, `verification-log.md` 순서
3. 진행 중·차단된 작업 카드와 현재 작업에 관련된 카드
4. [PRD/디자인 문서][prd]와 현재 작업에 관련된 추가 명세
5. [DESIGN.md][design]: UI·반응형·상호작용 기준
6. [제품 구현 계획][app-plan] 중 현재 작업의 단계와 파일 책임

새 세션이나 휴식 후에는 기본 문서 6개를 읽어 맥락을 복구한다.
추가 기능 수정·구현 전에도 메모리를 먼저 확인한 뒤 필요한 기준 문서를 읽는다.
제품 코드 조사·편집과 의존성 설치는 이 확인과 작은 작업 카드 준비 후 시작한다.
같은 세션의 후속 작업에서는 변경된 기록과 관련 근거를 중심으로 읽는다.
완료된 모든 카드와 원본 문서 전체를 매번 다시 읽거나 노트로 복사하지 않는다.
필요한 코드·설정의 존재와 실제 검사 결과를 대조하고, 계획을 구현된 사실로 쓰지 않는다.
환경 변수 파일·인증 캐시·개인 계정 자료를 메모리 작성 목적으로 열지 않는다.

## 현재 11-7 범위

- 앱은 실시간 방명록이다. 개인 계정과 무관한 합성 샘플 데이터를 먼저 사용한다.
- 실제 Supabase 연결은 사용자가 명시적으로 요청하기 전까지 범위 밖이다.
- 로그인·회원가입과 익명 인증 연결을 현재 작업의 선행 조건에 넣지 않는다.
- 기존 PRD의 전체 제품 목표와 현재 11-7 범위를 구분해 기록한다.
  PRD에 연동 계획이 있어도 이를 현재 구현 승인으로 해석하지 않는다.
- 실제 연동이 요청되면 대상·작업 범위를 확인하고 해당 지침에 따라 처리한다.
- 임시 `.superpowers/` 시안의 데이터·체험 이벤트·접근 키를 복사하지 않는다.
- 샘플·로컬 동작 검증과 실제 저장·인증·두 세션 간 실시간 검증을 구분한다.

최신 사용자 요청을 우선한다. 제품 정책과 인수 기준은 PRD, UI 값은 `DESIGN.md`를 따른다.
기록이 문서·현재 파일과 충돌하면 차이를 표시하고 근거를 확인한다.
제안을 사용자 확정 사항으로 바꾸거나 메모리만 수정해 제품 정책을 변경하지 않는다.

## 기본 문서와 누락 파일 생성

스킬 사용 시 `.memory-bank/`에 없는 기본 파일만 생성한다.
부분 구성에서도 기존 문서와 사용자 메모를 빈 양식으로 덮어쓰지 않는다.
명시적인 파일 변경 금지 요청이 있으면 생성·갱신 없이 누락 상태만 보고한다.
다른 `memory-bank/` 폴더를 자동 이동·삭제·병합하지 않는다.

| 파일 | 기록할 내용 |
| --- | --- |
| `project-brief.md` | 앱 목적, 전체 목표와 현재 범위, 기준 문서 링크 |
| `active-context.md` | 현재 초점, 진행 중 작업, 중단 지점과 차단 사유 |
| `progress.md` | 작업별 상태, 짧은 결과, 카드·검증 기록 링크 |
| `decision-log.md` | 결정일·범위·결정·이유·출처, 제안/확정 구분 |
| `next-actions.md` | 다음 행동, 우선순위·선행 조건, 관련 카드 |
| `verification-log.md` | 실행일·환경·실제 검사·결과, 실패·미검증 |

각 파일에 제목, 최종 갱신일, 짧은 내용과 필요한 근거·미확인 사항을 둔다.
근거 링크는 생성된 노트 파일에서 원본으로 해석되는 상대 경로로 작성한다.
모르는 사실은 `미확인`으로 남기고, 현재 요청·파일·검사에서 확인한 내용만 채운다.
`decision-log.md`는 사용자 결정·문서 기준·작성자 제안을 구분한다.
결정 변경 시 이전 결정을 보존하고 새 결정과 대체 관계를 남긴다.
날짜는 사용자 시간대의 현재 날짜를 사용하고 과거 기록의 날짜를 바꾸지 않는다.

## 작업 상태와 검증

작업 카드와 `progress.md`에 다음 4개 상태를 사용한다.

| 상태 | 의미 |
| --- | --- |
| `done` | 해당 작업의 완료 조건과 필요한 검증을 충족함 |
| `in progress` | 시작했으며 아직 완료 조건을 모두 충족하지 못함 |
| `blocked` | 정보·환경·의존성 문제로 진행할 수 없음 |
| `next` | 아직 시작하지 않은 다음 작업 후보 |

`blocked`에는 원인과 해제 조건을 적는다. 누락 메모리 파일 자체를 차단 사유로 삼지 않는다.
검증은 상태와 별도로 `통과`·`실패`·`미검증`으로 기록한다.
예정된 검사와 실제 실행을 구분하고, 실행일·환경·명령/절차·결과를 짧게 남긴다.
`package.json`과 실제 스크립트가 없으면 계획에 있는 앱 검사를 실행 가능하다고 쓰지 않는다.
필수 검증이 남으면 `done`으로 바꾸지 않는다. 환경 때문에 진행할 수 없으면 `blocked`다.
빌드·mock·HTTP 응답·구독 로그만으로 실제 DB 권한·전체 기능·배포 인수 통과를 주장하지 않는다.
완료 범위가 샘플 UI라면 그 범위의 검증으로 판단하고 실제 연동은 별도의 미검증으로 남긴다.

## 작은 작업 준비

현재 범위와 `next-actions.md`에서 검토 가능한 작은 작업 하나를 고른다.
`.memory-bank/tasks/`에 같은 작업의 카드가 있으면 갱신하고, 없으면 생성한다.
파일명은 `YYYY-MM-DD-short-task-name.md`를 사용한다.
다른 작업과 이름이 겹치면 짧은 접미사를 붙이고 기존 파일을 덮어쓰지 않는다.

카드에는 다음 항목을 짧게 작성한다.

- 제목·최종 갱신일·적용 범위
- 상태: 준비만 했다면 `next`, 실제 시작했다면 `in progress`
- 목표: 끝나면 달라질 동작 한 가지
- 관련 문서와 예상 변경 파일
- 할 일과 제외할 일
- 완료 조건과 예정된 검증
- 실제 결과·실행한 검증·미검증
- 차단 사유·해제 조건 또는 다음 행동

카드 링크를 진행 상황과 다음 행동에 연결하고 상세 설명을 여러 노트에 반복하지 않는다.
계획만 요청되면 노트·카드 작성 후 멈추고, 구체적인 계획을 제시한 뒤 코드 편집 전 확인한다.
카드 생성은 앱 코드 편집·의존성 설치·외부 연결의 승인이 아니다.
이미 해당 구현을 명시적으로 요청받았다면 같은 승인을 반복해서 요구하지 않는다.

## 완료 요약과 작업 인계

1. 실제 변경, 남은 작업과 실행한 검증을 확인한다.
2. 해당 카드와 `progress.md`의 상태를 맞춘다.
3. `verification-log.md`에 실행 결과와 실패·미검증을 기록한다.
4. `active-context.md`에 현재 상황과 중단 지점을 남긴다.
5. `next-actions.md`에 다음 행동과 선행 조건을 정리한다.
6. 새 결정이나 범위 변경이 있을 때만 결정 기록·프로젝트 요약을 갱신한다.

해당 요청의 범위에서 변경된 부분만 수정한다.
변경 없는 노트를 다시 쓰거나 이미 통과한 검사를 이유 없이 반복하지 않는다.
해결된 문제는 해결 근거를 남기고 현재 미해결 문제와 구분한다.

## 저장 금지와 변경 경계

- 비밀번호, API 키, 토큰, Supabase URL 값, 개인 계정 데이터를 저장하지 않는다.
  공개 키·공개 Supabase URL도 실제 값은 기록하지 않는다.
- 이 규칙을 메모리·카드·명령 예시·검사 결과 모두에 적용한다.
  환경 변수는 이름과 역할만 적고, 로그는 금지 값을 제거한 결과만 요약한다.
- 저장 직전에 작성할 내용에 금지 정보가 섞였는지 확인한다.
  발견하면 값을 복사·인용하지 말고 필요한 경우 제거 사실만 기록한다.
- 다른 앱·사용자 홈·전역 Codex 메모리·설정을 수정하지 않는다.
- 이 스킬 호출을 DB 변경·배포·외부 메시지 전송의 승인으로 해석하지 않는다.
- 기존 변경·사용자 메모를 보존하고 관련 없는 파일을 스테이징하지 않는다.

## 결과 전달

한국어로 현재 범위와 `done`·`in progress`·`blocked`·`next`를 짧게 전달한다.
읽은 근거, 생성·갱신한 파일, 실제 검증 결과와 남은 미검증을 구분한다.
초기화만 했다면 앱 구현이 완료된 것처럼 보고하지 않는다.
계획만 준비했다면 해당 카드와 구현 전 확인할 내용을 제시한다.
