# 두 워크트리 FAQ 병렬 작업

최종 갱신일: 2026-10-15
상태: `done`
적용 범위: 랜딩 FAQ 내용 보강·카테고리 필터·두 작업의 병합 검증

## 목표와 작업 분담

사용자가 제안된 FAQ 예제를 선택하고 두 서브 에이전트의 병렬 구현을 요청했다.
같은 기준 커밋에서 두 워크트리를 만들고 같은 LandingPage.tsx를 각각 수정한다.

- [워크트리 A](2026-10-15-faq-content-worktree.md): 답변 개선과 이미지·그림 질문 추가.
- [워크트리 B](2026-10-15-faq-category-worktree.md): 카테고리 데이터와 접근 가능한 필터.
- 통합 담당: 공유 메모리·PRD·DESIGN·작업 예제 문서·병합 충돌·통합 검증.

## 예정 구조와 경계

- A: `.worktrees/faq-content/`, 브랜치 `feature/faq-content`.
- B: `.worktrees/faq-category/`, 브랜치 `feature/faq-category`.
- 현재 작업 폴더는 통합 브랜치 `demo/faq-parallel`에서 두 결과를 병합한다.
- FAQ의 공개 여부·세션 권한·이미지와 그림 상한은 기존 PRD를 따른다.
- 원격 push·운영 배포·DB 변경은 이번 요청에 포함하지 않는다.
- 워크트리·기존 임시 기록·의존성은 제품 커밋에 포함하지 않는다.

## 완료 조건과 검증

- 두 에이전트가 분리된 워크트리에서 병렬로 같은 파일을 수정하고 각각 커밋한다.
- 통합 결과에 보강한 질문과 카테고리 필터가 모두 남아 있다.
- 타입·빌드·관련 E2E, 전체/개별 필터·FAQ 펼침·키보드·모바일 검증을 통과한다.
- 실제 충돌 경로와 해결 방법, 기준·결과 커밋을 예제 문서에 기록한다.

## 실제 결과와 다음 행동

같은 준비 커밋 `44677f9`에서 두 워크트리를 만들고 서브 에이전트가 병렬 구현했다.
A는 `0b7e711`, B는 `f77ba42`에 독립 커밋했다. 각 워크트리는 그대로 보존했다.
A 병합 `51ba737` 후 B 병합에서 LandingPage.tsx의 questions 영역이 충돌했다.
A의 보강 문답 6개를 B의 객체 구조에 넣고 새 문답 2개를 첨부로 분류했다.
해결한 병합 커밋은 `f1b5312`다. 작업 과정은 [실행 예제](../../docs/faq-worktree-example.md)에 있다.

- A 전용 실제 Chrome E2E 2개, B 전용 2개: 각각 통과.
- 통합 빌드·타입 검사, 단위 테스트 22개, 관련 실제 Chrome E2E 6개: 통과.
- FAQ 전체 6개, 작성 1개·첨부 3개·권한 2개를 유지했다.
- 320px 키보드·44px 버튼·줄바꿈·FAQ 펼침·API 추가 요청 없음: 통과.
- 직접 화면 캡처는 도구 승인 정책으로 실행되지 않아 별도 시각 검수는 미검증이다.
- 원격 push·운영 배포·DB 변경은 수행하지 않았다.
