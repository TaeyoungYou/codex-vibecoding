# Vercel 미리보기 배포

최종 갱신일: 2026-10-14
상태: `done`
적용 범위: 방명록 전용 Vercel 대상·공개 환경 변수·빌드·미리보기 검증

## 목표와 근거

사용자가 `vercel-cli`와 `deploy-to-vercel` 스킬을 사용한 배포를 요청했다.
[구현 계획][plan]과 [PRD][prd]의 실제 배포 기준을 따른다.
프로덕션 요청은 없으므로 먼저 미리보기 배포를 준비한다.

## 할 일과 완료 조건

- 기존 변경을 보존하고 방명록 전용 Vercel 계정·프로젝트를 확인한다.
- 실제 빌드 스크립트와 공개 환경 변수만 사용하며 비밀 파일을 업로드하지 않는다.
- 필요한 배포 설정과 README를 정리하고 빌드·배포 상태를 확인한다.
- 실제 배포 화면과 주요 연동을 검증하고 URL·결과·미검증을 전달한다.

예상 변경 파일은 배포 설정·README와 관련 메모리 노트다.
다른 앱·DB 구조·유료 요금제 변경은 제외한다.
Git push 방식이 필요하면 구체적인 변경을 준비한 뒤 스킬의 명시 승인 규칙을 따른다.

## 실제 결과와 다음 행동

메모리 기본 문서 6개와 관련 연동·점검 카드를 확인했다.
기존 Supabase 연동은 검증 이력이 있으며 Vercel 배포는 이번에 시작한다.
전역 CLI 대신 고정 버전 64.0.2를 사용하고 전용 프로젝트를 새로 연결했다.
`vercel.json`·`.vercelignore`를 추가하고 `.gitignore`·README를 갱신했다.
Preview에 공개 변수 3개만 등록했고 배포 파일 목록에서 환경·서버 파일을 제외했다.
실제 대상은 기존 방명록 전용 Supabase와 일치한다.

- 타입 검사·빌드, 실제 배포 Ready와 Preview target: 통과.
- 첫 배포가 Production으로 초기화돼 Preview를 다시 생성했다.
  이번에 만든 초기 Production 배포를 삭제했고 최종 목록에는 Preview 1개만 있다.
- 실제 두 익명 세션의 인증·혼합 저장·그림 획 재편집·실시간 생성/수정: 통과.
- 동일 닉네임 타인의 편집·삭제 RPC와 직접 쓰기 거절: 통과.
- 열린 초안 유지·재방문·오프라인 삭제 후 재연결 복구: 통과.
- 데스크톱·390px·320×568 작성과 Tab 초점 제한: 통과, 가로 넘침 없음.
- 실제 미디어 3개 물리 정리, 검증 게시물 정리와 기존 데이터 보존: 통과.
- 테스트 구간 브라우저 런타임 오류: 0개.
- 실제 배포 JS의 공개 연결 일치·작업자 비밀과 로컬 OIDC 값 미포함: 통과.

미리보기 URL은 [README의 배포 안내][readme]에 둔다.
미리보기는 Vercel 로그인 보호를 유지하며 테스트는 인증된 접근을 사용했다.
Git push·자동 배포 연결·공개 운영 배포는 진행하지 않았다.
617 kB 번들 경고와 기존 전체 인수·실기기 검증 공백은 남아 있다.
제품 동작·DB 구조는 변경하지 않았고 기존 단위·DB 검사를 반복하지 않았다.
