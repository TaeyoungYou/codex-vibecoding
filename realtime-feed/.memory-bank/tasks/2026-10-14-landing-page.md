# 방명록 랜딩페이지

최종 갱신일: 2026-10-14
상태: `done`
적용 범위: `realtime-feed`의 서비스 소개와 기존 방명록 진입

## 목표와 근거

사용자가 프로젝트 안에 랜딩페이지 구현을 요청했다.
[PRD](../../docs/superpowers/specs/2026-10-11-realtime-guestbook-design.md)의
글·이미지·그림과 실시간 피드를 소개하고 실제 방명록으로 연결한다.
[UI 기준](../../DESIGN.md)의 흑백 라이트 테마와 접근성을 이어받는다.

## 할 일과 제외할 일

- 소개·콘텐츠 미리보기·사용 방법·FAQ·방명록 진입을 구현한다.
- 소개용 예시는 실제 방문자 게시물과 구분한다.
- 기존 피드·인증·저장·DB는 보존하며 외부 배포는 이번 작업에서 하지 않는다.
- 예상 파일: `src/main.tsx`, 랜딩 컴포넌트·CSS, README·디자인·PRD, 메모리.

## 완료 조건과 예정된 검증

- 타입 검사와 프로덕션 빌드 통과.
- 데스크톱·390px·320px 반응형, 키보드·FAQ·진입 링크 확인.
- 기존 방명록 회귀 검사와 새 경로의 직접 방문 확인.

## 실제 결과와 다음 행동

`/`에 랜딩, `/guestbook`에 기존 앱을 두고 지연 로드했다.
글·사진·그림의 예시와 선택형 미리보기, 이용 방법·FAQ·모바일 메뉴를 추가했다.
기존 앱의 로고는 소개로 연결하며 Vercel에 직접 진입 rewrite를 추가했다.
새 의존성 없이 기존 피드·인증·저장 코드를 보존했다.
PRD·디자인·구현 책임·README와 E2E 경로를 갱신했다.

- Linux·Node 24·Chromium: 타입 포함 빌드, 단위 22개, E2E 4개 통과.
- 320·375·390·600·768·820·1,024·1,440px에서 넘침 없음과 이미지 로드 확인.
- 진입·새로고침·홈 복귀·뒤로 가기, 키보드·Escape·reduced-motion 확인.
- 소개에서 API 요청 0개, 수동 브라우저 검사에서 런타임 오류 0개.
- 초기 검사의 제목 줄바꿈 locator를 정정한 뒤 E2E 전체 통과.
- [검증 기록](../verification-log.md)에 검사 범위와 미검증을 구분했다.

차단 없음. 다음은 사용자 화면 확인과 필요 시 운영 반영이다.
실제 서비스 데이터·실기기·외부 배포는 이번 작업의 검증 범위 밖이다.
