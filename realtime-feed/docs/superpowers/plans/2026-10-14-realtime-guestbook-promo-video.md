# Realtime Guestbook 홍보영상 제작 계획

작성일: 2026-10-14
상태: 사용자 제작 요청에 따라 구현·MP4·포스터 출력 완료(2026-10-14).

[실제 납품·검수 결과][delivery-review]와 [Remotion 소스 안내][video-readme]를 참고한다.
아래의 미준비·예정 설명은 계획 작성 당시 상태이며 현재 검수 결과와 구분한다.

## 1. 목적과 확정 조건

실제 방문자가 방명록에 인사를 남기고 싶어지는 짧은 제품 홍보영상을 만든다.
현재 웹앱의 흑백·라이트 분위기를 유지하고 포트폴리오에도 사용할 완성도를 목표로 한다.
시청 후에는 닉네임으로 시작해 글·이미지·그림을 남길 수 있다는 점이 기억되어야 한다.

| 구분 | 사용자 요청으로 확정된 내용 |
| --- | --- |
| 대상 | 실제 방명록을 사용할 방문자 |
| 길이 | 25~35초 |
| 해상도 | 1920×1080, 가로 16:9 |
| 프레임 | 30fps |
| 시각 방향 | 현재 웹앱 테마와 유사하게 |
| 품질 | 포트폴리오에 사용할 수준 |
| 제작 도구 | Remotion 플러그인·React 기반 제작 |
| 필수 이미지 | 지정된 히어로 v2·작성 장면 v2·포트폴리오 PNG |
| 사운드 | 잔잔한 음악·효과음, 내레이션 없음 |
| 이번 작업 | 계획 Markdown 작성부터 진행 |

**제작자 제안:** 기본 길이는 30초, 총 900프레임으로 잡는다.
아래 장면 순서·카피·서체 크기·모션·음악 세부 값은 계획 검토용 제안이다.
이 문서 확인 후 제작 단계로 넘어간다.

## 2. 기준 문서와 현재 상태

- [제품 요구사항][prd]: 닉네임, 글·이미지·그림, 공개 피드와 실시간 반영의 근거.
- [DESIGN.md][design]: 흑백·라이트·단일 열·얇은 경계·선형 아이콘의 기준.
- [현재 앱][app]과 [실제 스타일][styles]: 화면 문구와 적용 중인 테마 확인.
- [이미지 생성 기록][image-plan]: 현재 선택은 v2이며 이전 종이·펜 이미지는 제외.
- [README][readme]: 실행 방법과 고정 운영 주소 확인.

현재 앱의 흰 배경·검은 버튼·중립 회색과 작은 꽃 낙서를 영상에서도 이어간다.
영상 프로젝트와 Remotion 의존성은 아직 없다. 음악·효과음·영상용 폰트도 미준비다.
기존 PNG 3종은 준비되어 있으며 이번 계획 작성에서 파일을 수정하지 않는다.

## 3. 핵심 콘셉트

**작은 인사 하나가 모여, 함께 머무는 공간이 된다.**

글·사진·그림 카드로 제품의 정체성을 먼저 보여주고,
노트북의 작성 장면에서 사용 경험을 전달한 뒤,
완성된 방명록 목업과 방문 유도로 마무리한다.

이미지에 느린 카메라 이동, 기능별 초점 이동, 짧은 타이포 모션을 더한다.
음악과 컷의 타이밍을 맞추고 모든 장면에서 주목할 대상은 하나씩 정한다.
정지 이미지의 손이나 입력값이 실제로 움직이는 것처럼 새 동작을 합성하지 않는다.
실시간 기능은 제품 카피로 설명하며 이번 이미지 영상은 기능 검증 기록과 구분한다.

## 4. 필수 이미지의 사용 방식

| ID | 입력 이미지 | 실제 크기 | 주 사용 장면 |
| --- | --- | --- | --- |
| A | [hero-background-v2.png][hero] | 1672×941px | 시작·글/이미지/그림 소개 |
| B | [leaving-a-note-v2.png][note] | 1448×1086px | 실제 작성 장면 |
| C | [portfolio-guestbook.png][portfolio] | 1672×940px | 제품 전경·마지막 방문 유도 |

### A. 카드 배경

실제 방명록의 아바타·닉네임·글·풍경 이미지·꽃 그림 카드가 담긴 이미지다.
오프닝에서는 카드가 보이는 구도를 유지하고 빈 공간에 영상 제목을 배치한다.
카피와 카드 글자가 겹치면 흰 그라데이션으로 카피 영역만 조용하게 정리한다.
중간에는 원본 안의 이미지·그림 카드에 초점을 옮겨 기능을 소개한다.

### B. 웹앱에 인사를 남기는 장면

노트북 화면의 실제 작성 모달과 손이 함께 보이는 컷을 사용한다.
4:3 이미지를 16:9로 늘이지 않고, 비율을 유지한 오른쪽 이미지 프레임에 배치한다.
왼쪽에는 짧은 카피를 둬 입력하는 장면과 읽는 영역이 경쟁하지 않게 한다.
카메라는 화면 쪽으로 천천히 다가가며 모달·키보드·손이 프레임 밖으로 잘리지 않게 한다.

### C. 완성된 제품 목업

노트북과 방명록 피드가 함께 보이는 정면 구도를 활용한다.
제품 전경을 보여준 뒤 여백을 확보하며 제품명·방문 유도·주소를 등장시킨다.
마지막에는 안정된 구도를 유지해 영상을 본 사람이 주소와 다음 행동을 기억하게 한다.

### 원본 해상도와 선명도

세 이미지 모두 1920px보다 가로 폭이 작다. 원본 비율과 글자 선명도를 우선한다.
A·C를 전체 폭에 쓰면 약 1.15배 확대되므로 추가 확대는 짧고 작게 제한한다.
B는 여백이 있는 편집 프레임에 넣어 원본보다 작게 배치하는 방향을 우선한다.
작은 UI 글자를 지나치게 확대해 주요 설명으로 사용하지 않는다.
영상용 카피는 Remotion의 실제 텍스트로 렌더해 한글을 선명하게 보여준다.
화질 문제 발견 시 구도와 배율부터 조정하고 원본의 UI를 생성형 이미지로 다시 그리지 않는다.

## 5. 30초 스토리보드와 프레임

프레임 구간은 시작 포함·끝 제외다. 마지막 출력 프레임은 899다.
전환은 아래 구간 안에서 처리해 합계 900프레임을 유지한다.

| 장면 | 시간 | 프레임 구간 | 프레임 수 | 이미지 |
| --- | --- | --- | --- | --- |
| 1 · 첫인상 | 0~4초 | 0~120 | 120 | A |
| 2 · 한 줄 남기기 | 4~10초 | 120~300 | 180 | B |
| 3 · 글과 이미지 | 10~15초 | 300~450 | 150 | A |
| 4 · 그림도 인사 | 15~20초 | 450~600 | 150 | A |
| 5 · 함께 보는 공간 | 20~25초 | 600~750 | 150 | C |
| 6 · 방문 유도 | 25~30초 | 750~900 | 150 | C |

합계: 120 + 180 + 150 + 150 + 150 + 150 = **900프레임 = 30초**.

### 장면 1 · 첫인상

- 카피: **“작은 인사, 함께 모아요.”**
- 보조 표기: `Realtime Guestbook`.
- A의 글·이미지·그림 카드를 보여주며 밝은 배경으로 시작한다.
- 첫 0.8초 안에 제품명과 카드가 보이고, 1초부터 핵심 카피가 자리 잡는다.
- 카드는 작은 이동으로 깊이를 주고 제목은 두 줄로 읽기 쉽게 배치한다.
- 2초 이상 카피를 충분히 읽은 뒤 작성 장면으로 이어간다.

### 장면 2 · 한 줄 남기기

- 카피: **“이름 정하고, 한 줄 남기기.”**
- B를 비율 유지 프레임에 보여주고 실제 작성 모달로 시선을 이끈다.
- 입력 문장·메시지 영역이 있는 화면을 중심으로 느린 줌을 준다.
- 한 번의 가벼운 클릭 효과음으로 장면 전환을 강조한다.
- 초점을 옮길 때 이미 입력된 내용이나 저장 상태를 임의로 변경하지 않는다.

### 장면 3 · 글과 이미지

- 카피: **“글도, 이미지도. 내 방식대로.”**
- A에서 글 카드와 풍경 카드가 보이는 영역을 순서대로 강조한다.
- 글 → 이미지로 시선이 이동하도록 마스크·구도 전환을 사용한다.
- 각 요소에 최소 1.5초를 주고 UI 글자 위에 추가 설명을 겹치지 않는다.
- 중간 설명을 위한 기술명·용량 제한·개발 과정은 화면 카피에 넣지 않는다.

### 장면 4 · 그림도 인사

- 카피: **“서툰 그림도, 좋은 인사가 돼요.”**
- A의 꽃 그림 카드를 중심으로 화면을 정리한다.
- 꽃 그림이 담긴 카드 자체를 부드럽게 나타내고 밝은 여백을 유지한다.
- 원본에 없는 펜 움직임이나 실제 캔버스 조작을 새로 만들어 넣지 않는다.
- 조용한 종소리 계열 효과음 한 번으로 장면의 친근한 분위기를 더한다.

### 장면 5 · 함께 보는 공간

- 카피: **“새로고침 없이, 인사가 이어져요.”**
- C의 전체 피드와 노트북 전경으로 전환해 콘텐츠가 모이는 공간을 보여준다.
- 제품의 실시간 반영을 설명하는 카피다. 정확한 지연 수치는 제시하지 않는다.
- 노트북의 구조를 유지하며 천천히 구도가 안정된다.
- 새로운 카드가 실제 서버에서 도착한 것처럼 이미지 안의 UI를 조작하지 않는다.

### 장면 6 · 방문 유도

- 주요 문구: **“오늘의 작은 흔적을 남겨보세요.”**
- 제품명: `Realtime Guestbook`.
- 행동 문구: **“인사 남기러 가기”**.
- 주소 표기 제안: `realtime-feed-henna.vercel.app`.
- C의 노트북과 브랜드를 함께 보여주며 실제 검은 버튼과 비슷한 CTA 스타일을 쓴다.
- 마지막 3초인 프레임 810~899는 CTA·주소를 고정해 읽을 시간을 준다.
- 영상 속 버튼은 시각적 안내다. 포트폴리오에서는 영상 아래 실제 링크로 연결한다.
- 주소는 README 기록을 참고했으며 최종 출력 전에 실제 공개 접속을 재확인한다.

## 6. 시각 디자인과 모션 기준

### 현재 테마에서 가져올 것

- 배경 `#FFFFFF`, 주요 텍스트·버튼 `#171717`.
- 보조 표면 `#FAFAFA`·`#F5F5F5`, 카드 경계 `#E5E5E5`.
- 본문 `#525252`, 보조 문구 `#737373`.
- 카드의 단정한 라운드와 얇은 경계, 선형 아이콘·꽃 낙서의 친근함.
- 이미지 속 풍경·꽃의 색은 유지하고 새로운 강조 색을 더하지 않는다.

### 영상용 제작 기본값

앱의 작은 글자를 그대로 확대한 화면보다 영상 프레임의 시선 흐름을 우선한다.
아래 값은 영상에만 적용하며 앱의 DESIGN.md 토큰을 변경하지 않는다.

| 항목 | 제작자 제안 |
| --- | --- |
| 한글/영문 | Pretendard / Inter, 로컬 폰트 파일 사용 |
| 첫 제목 | 약 150px, 700 굵기, 짧은 두 줄 |
| 장면 카피 | 80~96px, 600~700 굵기, 최대 두 줄 |
| CTA | 64~80px, 600~700 굵기 |
| 제품명·주소 | 40~56px, 선명한 대비로 표시 |
| 안전 여백 | 중요 요소는 좌우 144px·상하 120px 안쪽 |
| 타이포 입장 | 10~16프레임, 불투명도·작은 수직 이동 |
| 장면 전환 | 12~18프레임의 밝은 디졸브 또는 부드러운 마스크 |
| 이미지 이동 | 느린 팬·2~4%의 작은 줌을 기본으로 |

문장이 프레임에 맞지 않으면 줄을 나눠 읽기 쉽게 정리한다.
한 장면에서 카메라·카드·글자가 동시에 크게 움직이지 않게 한다.
손이 포함된 B는 하나의 사진으로 유지하고 카메라 이동만 준다.
글자 반짝임·강한 흔들림·과한 튕김·급격한 시점 변화는 사용하지 않는다.
완전한 검은 화면으로 시작하거나 끝내지 않고 제품 분위기를 유지한다.

## 7. 음악과 효과음

잔잔한 음악과 효과음, 내레이션 없는 구성은 사용자 선택이다.
세부 음악은 제작 전에 확보해야 하며 아직 선택된 파일은 없다.

- 음악 제안: 보컬 없는 미니멀 피아노·부드러운 전자 악기, 약 90~105 BPM.
- 도입 0.5~1초 페이드인, 종료 1~1.5초 페이드아웃.
- 전체 30초를 자연스럽게 이어주는 구간을 선정하고 반복 경계가 들리지 않게 한다.
- 효과음은 장면 2의 클릭, 장면 4의 가벼운 종소리 등 총 2~4회 이내.
- 효과음이 배경 음악보다 갑자기 튀지 않게 음량을 조절한다.
- 재생 환경에 따른 과도한 볼륨 차이와 클리핑을 최종 출력에서 확인한다.
- 음악·효과음·폰트의 홍보영상·포트폴리오 사용 권한과 출처를 기록한다.
- 소리를 끄고 보아도 화면 카피만으로 모든 메시지를 이해할 수 있어야 한다.

## 8. Remotion 구현 방식과 파일 책임

기존 앱과 분리된 `video/realtime-guestbook-promo/`를 제작 위치로 제안한다.
현재 이 폴더와 아래 파일은 없으며 계획 확인 후 생성한다.
루트 앱의 실행·빌드·배포 구성을 바꾸지 않는다.

| 예정 파일 | 책임 |
| --- | --- |
| `package.json`, `package-lock.json` | 영상 의존성·실행·형식 검사 명령 |
| `src/index.ts`, `src/Root.tsx` | 진입점, Composition 등록 |
| `src/PromoVideo.tsx` | 900프레임 장면과 사운드 구성 |
| `src/timeline.ts` | 장면 구간·길이·전환 값 |
| `src/copy.ts`, `src/theme.ts` | 확정 카피·색상·서체·크기 |
| `src/scenes/` | 위 6개 장면의 레이아웃·초점·입장 모션 |
| `src/components/` | 이미지 프레임·카피·CTA·공통 전환 |
| `public/images/` | 지정된 PNG 3개의 영상용 복사본 |
| `public/audio/`, `public/fonts/` | 확정 음악·효과음·폰트 파일 |
| `ASSET_LICENSES.md` | 자산 출처와 사용 권한 기록 |
| `README.md` | 미리보기·출력·검수 방법 |

Composition 제안은 `RealtimeGuestbookPromo`, 너비 1920, 높이 1080,
fps 30, `durationInFrames` 900이다.
설정 방식은 [Remotion Composition 공식 문서][remotion-composition]를 따른다.

이미지는 `Img`·`staticFile`로 불러오고 원본 비율을 보존한다.
모든 움직임은 현재 프레임과 `interpolate`에 따라 결정되게 만든다.
CSS 시간 애니메이션이나 실제 시각에 의존하지 않아 미리보기와 출력이 일치하게 한다.
관련 기준은 [Remotion 애니메이션 공식 문서][remotion-animation]에서 확인했다.

음악·효과음도 영상 타임라인에 맞춰 배치하고 볼륨 페이드를 프레임으로 제어한다.
오디오 API는 [공식 오디오 문서][remotion-audio]와 실제 설치 버전에서 확인한다.
Remotion 패키지는 제작 시 검증한 같은 버전으로 고정하고 lockfile을 관리한다.
직접 작성하는 클래스는 `Promo__Copy` 같은 BEM을 기본으로 한다.

## 9. 제작 순서와 확인 시점

1. **계획 확인:** 장면 순서·카피·30초 기본안·필수 이미지 사용을 확인한다.
2. **소스 준비:** 이미지 3종 복사, 음악·효과음·폰트 확보와 사용 권한 기록.
3. **프로젝트 준비:** 별도 영상 폴더에 Remotion 구성, 버전 고정·스크립트 정의.
4. **Studio 먼저 실행:** 빈 구성부터 브라우저에 열어 작업 중 미리보기를 유지한다.
5. **정지 레이아웃:** 각 장면의 한 프레임씩 구성해 카피·이미지·안전 여백을 확인한다.
6. **모션과 사운드:** 900프레임 타임라인에 카메라·전환·음악·효과음을 맞춘다.
7. **전체 미리보기:** 무음·소리 포함 재생을 각각 확인하고 읽는 시간을 보완한다.
8. **최종 출력:** 확인된 구성으로 MP4와 포스터 PNG를 출력하고 실제 파일을 검수한다.
9. **기록 정리:** 출력 사양·파일 위치·자산 출처·검수 결과와 남은 사항을 기록한다.

제작 중 기술 세부 값은 검증한 버전과 `--help`에 맞춰 조정한다.
현재는 계획만 작성하므로 위 단계의 프로젝트 생성·미리보기·출력 명령을 실행하지 않는다.

## 10. 출력과 납품 계획

예정 납품 파일은 프로젝트 루트의 `output/video/`에 저장한다.
아래는 아직 존재하지 않는 예정 경로이며 이전 출력이 생기면 버전 이름으로 보존한다.

- `output/video/realtime-guestbook-promo.mp4`: 30초 홍보영상.
- `output/video/realtime-guestbook-promo-poster.png`: 1920×1080 대표 프레임.
- `output/video/realtime-guestbook-promo-review.md`: 실제 검사·자산 사용 기록.
- 별도 Remotion 소스와 lockfile: 카피·이미지·모션을 다시 수정할 수 있게 보관.

출력 제안은 MP4·H.264·AAC·`yuv420p`다.
CRF 16을 시작점으로 잡고 UI 글자 선명도와 파일 크기를 보고 조정한다.
옵션은 [공식 render CLI 문서][remotion-render]에서 확인했다.

다음은 **영상 폴더가 준비된 뒤 사용할 예정 명령**이다.
PowerShell에서 `video/realtime-guestbook-promo/`를 작업 폴더로 사용한다.
긴 출력 명령은 PowerShell 배열로 인자를 전달한다.

```powershell
npx.cmd remotion studio --no-open

$renderArgs = @(
  'remotion', 'render', 'src/index.ts', 'RealtimeGuestbookPromo',
  '../../output/video/realtime-guestbook-promo.mp4',
  '--codec=h264', '--audio-codec=aac', '--pixel-format=yuv420p',
  '--crf=16', '--overwrite=false'
)
npx.cmd @renderArgs

npx.cmd remotion still src/index.ts RealtimeGuestbookPromo `
  ../../output/video/realtime-guestbook-promo-poster.png --frame=825
```

포스터는 CTA가 자리 잡은 27.5초 지점의 프레임 825를 기본으로 제안한다.
최종 제작에서 더 좋은 대표 장면이 있으면 포스터 선택만 변경할 수 있다.

## 11. 포트폴리오용 품질 인수 기준

### 내용과 시각 품질

- [ ] 지정된 PNG 3종이 각각 의미 있는 장면에서 사용되었다.
- [ ] 처음 3초 안에 온라인 방명록의 카드와 제품명이 보인다.
- [ ] 닉네임·글·이미지·그림과 함께 보는 공간의 장점이 이해된다.
- [ ] 기존 테마의 흰 배경·검은 주요 요소·중립 회색·여백을 유지한다.
- [ ] 카피를 멈추지 않고 읽을 수 있고 CTA·주소가 마지막 3초 동안 유지된다.
- [ ] 한글 잘림·오타·줄바꿈 오류·UI 글자와 카피의 겹침이 없다.
- [ ] 1920×1080 실제 크기에서 이미지가 늘어나거나 과하게 흐려지지 않는다.
- [ ] 960×540 재생에서도 주요 카피·버튼·제품명이 읽힌다.
- [ ] 손·카드·노트북을 변형하지 않고 전환 중 깜빡임·빈 프레임이 없다.
- [ ] 음악과 효과음이 자연스럽고 무음에서도 메시지가 전달된다.
- [ ] 모든 자산 출처·사용 권한과 CTA의 공개 운영 주소를 확인했다.

### 실제 출력 검사

- [ ] 메타데이터가 1920×1080·30fps·900프레임·30초인지 확인했다.
- [ ] 25~35초 요구 범위, H.264 비디오·AAC 오디오와 정상 재생을 확인했다.
- [ ] 0·119·120·299·300·449·450·599·600·749·750·810·899프레임을 검사했다.
- [ ] 실제 MP4를 브라우저와 영상 플레이어에서 처음부터 끝까지 재생했다.
- [ ] 최종 포스터·소스·출력 영상의 이름과 기록이 일치한다.

메타데이터는 [Remotion ffprobe][remotion-ffprobe] 등 실제 출력 분석 도구로 확인한다.
Studio 정상 표시만으로 최종 파일의 품질 검사를 통과했다고 기록하지 않는다.
실행할 검사 스크립트는 영상 프로젝트 생성 후 실제 정의된 명령만 사용한다.

## 12. 현재 남은 제작 준비

- 계획안의 30초 구성·카피·제작 순서 확인.
- 잔잔한 음악 1곡·효과음 2~4개·폰트 파일과 사용 권한 확보.
- Remotion 별도 프로젝트와 실행 가능한 미리보기·출력 환경 준비.
- 실제 1080p 장면 구성, 음향 믹싱, 최종 MP4·포스터 검수.

필수 이미지는 준비되었고 음악 구성은 사용자 선택을 반영했다.
원격 서비스 촬영·새 이미지 생성·웹앱 기능 변경은 이 제작안의 선행 조건으로 두지 않는다.
이번 완료 범위는 계획 문서이며 영상 파일·브라우저 미리보기·최종 품질은 미검증이다.
