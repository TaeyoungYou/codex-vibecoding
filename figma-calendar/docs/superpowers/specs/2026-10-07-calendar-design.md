# 피그마 기반 캘린더와 날짜별 일정 카드 설계

- 작성일: 2026-10-07
- 작업 위치: `figma-calendar/`
- 상태: 2026-10-07 사용자 문서 검토 및 구현 진행 승인 완료.
- 기술 구성: 기본 HTML, CSS, JavaScript
- 현재 작업 범위: 승인된 설계의 구현 및 검증

## 1. 목적과 확정된 요구사항

피그마의 캘린더 디자인을 바탕으로 월별 달력을 만들고, 사용자가 날짜를 선택하면 해당 날짜의 일정을 확인하고 간단히 추가·삭제할 수 있도록 한다.

사용자가 확정한 요구사항은 다음과 같다.

1. `figma-calendar/` 안에 기본 HTML, CSS, JavaScript로 작성한다.
2. 제공된 두 피그마 화면을 달력 디자인의 기준으로 사용한다.
3. 날짜를 선택하면 달력과 비슷한 디자인의 일정 컴포넌트를 표시한다.
4. 일정 기능은 목록 보기, 간단한 추가, 삭제를 제공한다.
5. 이번 단계에서는 설계 문서를 작성한다. 제품 코드 작성은 별도 단계에서 진행한다.

대화에서 제시하고 승인받은 구성은 달력 아래 일정 카드 배치, 현재 월로 시작, 월 이동 시 선택 해제, `localStorage` 저장이다. 일정의 입력 정보는 제목 하나이며 목록은 추가한 순서대로 표시한다.

일정 카드는 참조 달력의 디자인 토큰을 재사용하는 신규 설계다. 피그마에서 확인한 기존 일정 카드로 취급하지 않는다.

### 공통 디자인 토큰

| 항목 | 기준 |
| --- | --- |
| 카드 배경 | 흰색 `#FFFFFF` |
| 기본 글자 | 검정 `#000000` |
| 선택 날짜 및 주요 버튼 | `#45539D` |
| 선택 날짜 및 주요 버튼 글자 | 흰색 `#FFFFFF` |
| 날짜 칸 테두리 | `#D5D4DF`, 1px |
| 앞뒤 월 날짜 배경 | `#F2F3F7` |
| 앞뒤 월 날짜 글자 | `#A8A8A8` |
| 카드 모서리 | 16px |
| 데스크톱 카드 안쪽 여백 | 30px |
| 달력 헤더와 요일 영역 사이 간격 | 12px |
| 기본 글꼴 | Inter, 한국어와 미지원 글자는 시스템 글꼴로 대체 |
| 달력 월 제목 | 24px, 굵기 900 |
| 요일 및 날짜 | 14px, 요일은 굵기 600 |

달력은 원본의 약 502px 너비를 데스크톱 기준으로 삼는다. 날짜 열은 일곱 개가 같은 너비를 가지며, 칸 경계선이 겹쳐 두껍게 보이지 않도록 한다. 원본의 그림자 없는 간결한 카드 표현을 유지한다.

피그마가 제공하는 화살표 SVG는 로컬 자산으로 저장해 사용한다. 실제 SVG의 크기와 비율을 유지하고, 버튼의 클릭 영역은 별도로 확보한다. 구현 시 임시 피그마 자산 URL을 제품 코드에 남기지 않는다.

## 3. 화면 구성

### 3.1 초기 화면

- 현재 월의 달력만 표시한다.
- 날짜는 선택되지 않은 상태다.
- 월 제목은 원본처럼 영문 월명과 연도를 표시한다.
- 요일은 원본처럼 `Mo`, `Tu`, `We`, `Th`, `Fr`, `Sa`, `Su`를 표시한다.
- 일정 카드는 숨겨져 있다.

### 3.2 달력 컴포넌트

달력은 월 제목, 이전·다음 월 이동 버튼, 요일 행, 날짜 영역으로 구성한다.

- 한 주는 월요일부터 일요일까지다.
- 해당 월에 필요한 4·5·6주를 계산해 표시한다.
- 앞뒤 월의 날짜는 회색 배경과 글자로 표시하며 선택할 수 없다.
- 해당 월의 날짜는 버튼으로 제공한다.
- 선택 날짜는 강조색 배경과 흰색 글자로 표시한다.
- 이전·다음 월 이동은 연도 경계를 포함해 동작한다.
- 탐색 버튼의 기본·비활성 디자인은 피그마의 상태를 따른다. 초기 앱의 월 이동에는 시작월·종료월 제한을 설정하지 않는다.

### 3.3 일정 컴포넌트

일정 카드는 달력 아래에 표시하며 달력과 같은 너비를 사용한다. 카드 사이 간격은 16px로 한다.

카드 내용은 다음 순서로 배치한다.

1. 선택한 날짜와 요일을 표시하는 제목
2. 일정 제목 입력란과 추가 버튼
3. 입력 또는 저장 오류 안내 영역
4. 해당 날짜의 일정 목록 또는 빈 상태 안내

선택한 날짜 제목은 한국어로 표시한다. 예를 들어 `2026년 10월 7일 수요일`처럼 연도·월·일·요일을 모두 포함한다.

일정 목록의 각 항목에는 제목과 삭제 버튼을 표시한다. 긴 제목은 줄바꿈하며, 삭제 버튼의 영역을 침범하지 않게 한다. 목록이 비어 있으면 `등록된 일정이 없습니다`를 표시한다.

## 4. 사용자 동작과 상태 전환

| 동작 | 결과 |
| --- | --- |
| 해당 월의 날짜 선택 | 선택 날짜를 강조하고 그 날짜의 일정 카드를 표시 |
| 다른 날짜 선택 | 강조 표시와 일정 카드의 날짜·목록을 함께 갱신 |
| 같은 날짜 다시 선택 | 선택 상태와 카드 표시 유지 |
| 이전·다음 월 이동 | 표시월 변경, 날짜 선택 해제, 일정 카드 숨김 |
| 일정 추가 | 제목을 저장하고 해당 날짜의 목록을 갱신 |
| 일정 삭제 | 해당 항목을 저장 데이터와 목록에서 제거 |
| 마지막 일정 삭제 | 빈 상태 안내 표시 |
| 새로고침 | 현재 월의 미선택 상태로 시작하고 저장된 일정 데이터 복원 |

날짜 변경 또는 월 이동 시 입력 중인 제목과 입력 오류 메시지는 초기화한다. 이미 저장된 일정은 유지한다. 표시월과 선택 날짜 자체는 영구 저장하지 않는다.

### 일정 추가

- 추가 버튼 클릭과 Enter 입력을 지원한다.
- 제목의 앞뒤 공백을 제거한다.
- 공백만 입력했으면 `일정 제목을 입력해 주세요`를 표시하고 입력란에 초점을 유지한다.
- 제목은 일반 텍스트로 표시한다. HTML로 해석하지 않는다.
- 제목이 같아도 각각 독립적인 일정으로 저장할 수 있다.
- 저장이 성공하면 입력란을 비우고 목록을 갱신한다. 초점은 입력란에 유지한다.

### 일정 삭제

- 항목별 삭제 버튼으로 해당 일정 하나를 삭제한다.
- 같은 제목의 다른 일정은 유지한다.
- 저장이 성공한 뒤 목록에 반영한다.
- 삭제 후에는 다음 항목의 삭제 버튼, 이전 항목의 삭제 버튼, 제목 입력란 순서로 가능한 위치에 초점을 옮긴다.

## 5. 상태와 저장 구조

앱은 한 곳에서 상태를 관리하고 달력과 일정 카드는 그 상태를 받아 화면을 갱신한다.

| 상태 | 의미 |
| --- | --- |
| 표시월 | 현재 달력에 표시하는 연도와 월 |
| 선택 날짜 | 사용자가 선택한 날짜 또는 미선택 상태 |
| 날짜별 일정 | 날짜 키별 일정 목록 |
| 저장소 상태 | 정상, 읽기 실패 또는 데이터 형식 오류 |
| 입력 오류 | 빈 제목 또는 최근 저장 실패에 대한 안내 |

날짜 키는 브라우저 로컬 날짜의 연도·월·일로 만든 `YYYY-MM-DD` 형식을 사용한다. UTC 변환 때문에 날짜가 전날이나 다음날로 바뀌지 않도록 한다.

### localStorage

- 저장 키: `figma-calendar.events.v1`
- 저장 형식: JSON
- 루트 정보: 형식 버전 1과 날짜별 일정 목록
- 각 일정의 정보: 고유 ID와 제목
- 목록 순서: 추가한 순서
- 저장 범위: 같은 브라우저의 같은 출처

고유 ID는 제목이나 목록 위치와 독립적이어야 한다. 추가·삭제는 저장이 성공한 뒤 앱 상태와 화면에 반영한다. 삭제로 해당 날짜의 목록이 비면 그 날짜의 빈 항목을 저장 데이터에서 정리한다.

## 6. 오류 처리

| 상황 | 사용자에게 보이는 동작 | 데이터 처리 |
| --- | --- | --- |
| 빈 제목 | 입력란 옆에 안내 | 새 일정 생성 없음 |
| 추가 저장 실패 | `일정을 저장하지 못했습니다. 다시 시도해 주세요` | 입력 내용과 기존 목록 유지 |
| 삭제 저장 실패 | `일정을 삭제하지 못했습니다. 다시 시도해 주세요` | 기존 항목 유지 |
| 저장소 읽기 실패 | `저장된 일정을 불러오지 못했습니다` | 일정 변경 기능 비활성화, 달력 탐색은 가능 |
| 저장 데이터 형식 오류 | 저장 데이터 오류 안내 | 원본 값을 덮어쓰지 않고 일정 변경 기능 비활성화 |

저장된 값이 없으면 정상적인 빈 데이터로 시작한다. 값이 존재하지만 파싱 또는 형식 검증에 실패한 경우는 읽기 오류로 처리하며, `등록된 일정이 없습니다`로 표현하지 않는다.

읽기 실패나 데이터 형식 오류 후에는 사용자가 원인을 해결하고 페이지를 새로고침하면 다시 읽는다. 앱이 저장 데이터를 자동으로 삭제하거나 초기화하지 않는다.

## 7. 파일과 책임

첫 구현은 다음과 같이 단순한 구조로 구성한다.

| 파일 또는 폴더 | 책임 |
| --- | --- |
| `index.html` | 앱의 기본 구조, 달력과 일정 카드의 표시 영역 |
| `styles.css` | 디자인 토큰, BEM 스타일, 반응형 레이아웃, 상태별 표현 |
| `app.js` | 초기화, 상태 관리, 날짜 계산, 달력·일정 카드 갱신, 저장소 접근 |
| `assets/` | 로컬 화살표 SVG 등 정적 자산 |
| `docs/superpowers/specs/` | 설계 문서 |

JavaScript 내부에서는 날짜 계산, 저장소 읽기·쓰기, 달력 갱신, 일정 카드 갱신의 책임을 나눈다. 달력 선택 동작은 앱의 선택 날짜를 갱신하고, 일정 카드는 그 날짜의 데이터만 표시한다. 달력과 일정 카드가 서로의 내부 DOM을 직접 변경하지 않도록 한다.

날짜 계산은 실제 월 길이, 윤년, 앞뒤 월 및 연도 이동을 기준으로 수행한다. 피그마 화면의 날짜 숫자를 그대로 하드코딩하지 않는다.

## 8. 반응형과 접근성

- 작은 화면에서는 카드가 화면 너비 안에 들어오도록 너비와 안쪽 여백을 줄인다.
- 일곱 날짜 열과 글자를 유지하면서 가로 스크롤이 생기지 않도록 한다.
- 일정 입력란과 추가 버튼은 공간이 부족하면 세로로 배치한다.
- 일정 제목과 삭제 버튼은 긴 제목에서도 구분해서 사용할 수 있게 한다.
- 날짜·월 이동·추가·삭제는 기본 버튼과 폼 동작을 사용한다.
- Tab으로 이동하고 Enter 또는 Space로 버튼을 실행할 수 있다.
- 월 이동 버튼에는 이전 달·다음 달을 구별하는 접근 가능한 이름을 제공한다.
- 날짜 버튼에는 연도·월·일을 포함한 이름과 선택 상태를 제공한다.
- 삭제 버튼의 이름에는 대상 일정 제목을 포함한다.
- 숨겨진 일정 카드의 내부 요소는 키보드 초점 대상에서 제외한다.
- 초점 표시를 제공하고, 오류 및 일정 변경 결과는 보조 기술에서도 알 수 있게 한다.
- 날짜 선택 시 초점을 강제로 일정 카드로 옮기지 않는다.

## 9. 검증과 완료 기준

다음은 향후 구현 단계의 검증 기준이다. 이번 문서 작성에서 제품 동작 검증을 수행한 것으로 간주하지 않는다.

### 디자인

- 2023년 5월과 6월을 표시해 피그마의 월 제목, 요일, 날짜 배치, 여백, 테두리, 글꼴과 비교한다.
- 2023년 5월 18일을 선택해 강조 상태를 비교한다.
- 원본의 화살표 자산이 정확한 위치와 비율로 표시되는지 확인한다.
- 일정 카드가 공통 토큰을 사용하며 달력 아래에 같은 너비로 표시되는지 확인한다.

### 날짜와 상태

- 2023년 5월과 6월의 날짜·요일 배치가 정확하다.
- 2024년 2월은 29일, 2025년 2월은 28일까지 표시한다.
- 2021년 2월, 2023년 5월, 2023년 10월은 각각 4·5·6주로 표시한다.
- 12월에서 다음 해 1월, 1월에서 이전 해 12월로 이동한다.
- 날짜를 바꾸면 선택 표시와 일정 카드의 날짜가 일치한다.
- 월 이동 시 선택 해제와 일정 카드 숨김이 함께 이루어진다.

### 일정과 저장

- 선택 날짜에 일정을 추가·삭제할 수 있다.
- 다른 날짜의 일정은 서로 섞이지 않는다.
- 같은 제목의 일정 중 특정 항목만 삭제할 수 있다.
- 마지막 일정 삭제 후 빈 상태가 표시된다.
- 새로고침 후 저장된 일정이 복원된다.
- 공백 제목 입력과 저장 실패에서 기존 데이터가 유지된다.
- 읽기 실패 또는 손상된 저장 데이터를 정상적인 빈 목록으로 표시하지 않는다.
- 마크업처럼 보이는 제목도 텍스트로 표시된다.

### 브라우저와 화면

- 데스크톱과 390px·320px 너비에서 가로 넘침과 버튼 겹침이 없다.
- 키보드로 날짜 선택, 일정 추가와 삭제가 가능하다.
- 새로 나타난 일정 카드와 오류 메시지가 접근 가능하다.
- 브라우저 콘솔에 앱으로 인한 오류가 없다.
