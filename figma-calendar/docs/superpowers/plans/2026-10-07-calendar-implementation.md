# 캘린더 구현 계획

- 작성일: 2026-10-07
- 기준: [승인된 설계](../specs/2026-10-07-calendar-design.md)
- 실행 방식: 사용자 구현 진행 승인에 따라 현재 세션에서 직접 구현
- 기술: HTML, CSS, JavaScript와 브라우저 기본 API

## 1. 자산과 기본 화면

- 최신 Figma 디자인 컨텍스트의 원본 화살표 SVG를 `assets/`에 저장한다.
- Inter 글꼴을 로컬 자산으로 준비하고 라이선스를 함께 보관한다.
- `index.html`에 달력, 처음에는 숨겨진 일정 카드, 상태 안내 영역을 구성한다.
- `styles.css`에 원본 토큰, BEM 스타일과 320px·390px 대응을 작성한다.

## 2. 날짜와 저장 처리

- `app.js`에서 로컬 날짜 키, 월 이동, 4·5·6주 날짜 배열을 계산한다.
- 버전 1의 날짜별 일정 데이터를 검증하고 `localStorage`를 읽고 쓴다.
- 쓰기 성공 후에만 앱 상태를 변경하고, 손상된 값은 덮어쓰지 않는다.
- Node 기본 테스트로 윤년, 월 경계, 주 수, 데이터 형식과 저장 실패를 확인한다.

## 3. 달력과 일정 동작

- 달력 갱신과 일정 카드 갱신을 별도 함수로 구성한다.
- 날짜 선택, 월 이동에 따른 선택 해제, 제목 입력·추가·삭제를 연결한다.
- 텍스트 제목, 중복 제목의 독립 ID, 빈 상태, 오류 안내를 처리한다.
- 키보드 조작, 선택 상태, 삭제 후 초점과 상태 알림을 제공한다.

## 4. 브라우저 검증과 전달

- 로컬 서버를 시작하고 실제 브라우저에서 달력을 확인한다.
- 날짜별 추가·삭제, 새로고침 복원, 빈 제목, 긴 제목을 확인한다.
- 2023년 5월·6월과 선택 상태를 원본 스크린샷에 비교한다.
- 데스크톱·390px·320px에서 넘침, 카드와 자산의 크기, 콘솔 오류를 확인한다.
- 실행 방법과 저장 범위를 `README.md`에 기록하고 실제 검증 결과를 전달한다.

`writing-plans` 스킬은 현재 설치되어 있지 않아 승인된 설계를 기준으로 이 계획을 직접 작성했다. 앱에 프레임워크나 빌드 도구 의존성을 추가하지 않는다.
